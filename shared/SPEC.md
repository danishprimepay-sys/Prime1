# SpamShield detection spec (v1)

This is the contract every SpamShield engine implements: the Kotlin engine
(`android/core`), the Swift engine (`ios/SpamShieldCore`) and the Python
reference (`reference/spamshield_ref.py`). All three must pass every file in
`shared/test-vectors/`. When behaviour changes, change this document, the
reference, and the vectors together.

Inputs that drive detection are data, not code:

| File | Purpose |
| --- | --- |
| `shared/rules.json` | Weights, thresholds, keyword rules, URL lists |
| `shared/model/sms_classifier.json` | Logistic-regression SMS classifier (generated by `ml/train.py`) |

## Regex dialect

All patterns (in this spec, `rules.json`, and the model's tokenizer) use only
the subset that behaves identically in Java, ICU (`NSRegularExpression`) and
Python `re`: literal characters, `.`, explicit ASCII classes such as `[0-9]`
and `[a-z]`, alternation, groups, `^`/`$`, `{m,n}`, `?`, `*`, `+` and negative
lookahead. No `\d`, `\s`, `\w`, `\b`, or inline flags. Patterns are applied to
text that has already been lowercased, so they are written in lowercase.
**Only `\n` is a line terminator**: `.` matches every character except `\n`
(including `\r`, U+0085, U+2028, U+2029), and `$` matches at the end of the
string or just before a final `\n` (Python's default). On the JVM compile with
`Pattern.UNIX_LINES`; with `NSRegularExpression` use `.useUnixLineSeparators`. "Find" means search anywhere in the string (not a full
match); `^` and `$` anchor to the whole string, not to lines.

Lowercasing is Unicode default lowercasing (`Locale.ROOT` on the JVM).

**Whitespace** (for trimming/removal in sections 1–2) is exactly Python's
`str.isspace` set: U+0009–U+000D, U+001C–U+001F, U+0020, U+0085, U+00A0,
U+1680, U+2000–U+200A, U+2028, U+2029, U+202F, U+205F, U+3000.

## 1. Number normalization — `normalize(raw, countryCode = "1")`

Returns a normalized address string, or `null` for "no number" (hidden caller).

1. If `raw` is null, or empty after trimming whitespace, return `null`.
2. If `raw` contains any ASCII letter `[A-Za-z]`, it is an alphanumeric sender
   ID: remove every whitespace character, uppercase (ASCII), and return it.
   (`"Amazon "` → `"AMAZON"`, `"john@example.com"` → `"JOHN@EXAMPLE.COM"`.)
3. `plus` = whether the first non-whitespace character is `+`. `digits` = all
   ASCII digits of `raw`, in order. If `digits` is empty return `null`.
4. If `plus`: return `"+" + digits`.
5. If `countryCode == "1"` and `digits` starts with `011` and is longer than 3:
   return `"+" + digits[3:]`.
6. If `digits` starts with `00` and is longer than 2: return `"+" + digits[2:]`.
7. If `countryCode == "1"`:
   - length 10 → `"+1" + digits`
   - length 11 and starts with `1` → `"+" + digits`
8. Else (other country codes): if `digits` starts with `0` and length ≥ 8,
   return `"+" + countryCode + digits[1:]`.
9. Otherwise return `digits` unchanged (short codes like `"72345"`, local
   numbers we cannot place).

### `isValidCallerNumber(n)`

True when `n` starts with `+` and:
- if it starts with `+1`: it is exactly 12 characters long, and the first
  digit of the area code (`n[2]`) and of the exchange (`n[5]`) are both
  in `2-9`;
- otherwise: 8 to 15 digits follow the `+`.

Everything else (short codes, alphanumeric, unplaceable digits) is invalid
*for calls*. SMS never uses this check.

### `isNeighborSpoof(caller, user)`

True when both are normalized, both start with `+1`, both have length 12, they
are not equal, and `caller[2:8] == user[2:8]` (same area code + exchange).

## 2. Number patterns (block/allow lists)

A list entry is a pattern string. To prepare an entry: if it contains `*` or
`?`, remove whitespace and the characters `( ) - .`, then ASCII-uppercase
(so `"+1 (800) 555-*"` → `"+1800555*"` and `"spam*"` → `"SPAM*"`); otherwise
run it through `normalize`. Skip the entry if the result is null or empty. Matching is a glob over the normalized
number: `?` matches exactly one character, `*` matches any run (including
empty), everything else is literal. The whole number must match.

`+1800555*` matches `+18005551234`; `+1212555????` matches `+12125550123`.

## 3. Evaluation — `evaluate(event, context) -> Verdict`

```
event   = { channel: "call" | "sms",
            number: string?,          // raw caller ID / sender
            body: string?,            // sms only
            isContact: bool,          // platform contacts lookup
            verification: "passed" | "failed" | "unknown" }   // STIR/SHAKEN, calls
context = { blocklist: [pattern], allowlist: [pattern],
            community: { normalizedNumber: score 0..1 },
            settings: { blockHiddenNumbers = false,
                        detectNeighborSpoofing = true,
                        userNumber: string? = null,     // raw, normalized on use
                        useClassifier = true,
                        useCommunity = true,
                        countryCode = "1" } }
Verdict = { action: "ALLOW" | "WARN" | "BLOCK", score: 0..1, reasons: [string] }
```

Steps, stopping at the first one that returns:

1. `n = normalize(event.number, settings.countryCode)`.
2. If `event.isContact` → `ALLOW, 0, ["contact"]`.
3. If `n != null` and any allowlist pattern matches → `ALLOW, 0, ["allowlist"]`.
4. If `n != null` and any blocklist pattern matches → `BLOCK, 1, ["blocklist"]`.
5. If channel is `call`, `n == null` and `settings.blockHiddenNumbers` →
   `BLOCK, 1, ["hidden_number"]`.
6. Collect signals `(id, weight)` in exactly this order; each id at most once:

   **Calls**
   - `hidden_number` — `n == null` → `call.hiddenWeight`
   - `verification_failed` — `verification == "failed"` → `call.verificationFailedWeight`
   - `invalid_number` — `n != null` and not `isValidCallerNumber(n)` → `call.invalidNumberWeight`
   - `neighbor_spoof` — `detectNeighborSpoofing`, `userNumber` normalizes to
     non-null `u`, and `isNeighborSpoof(n, u)` → `call.neighborSpoofWeight`
   - `community` — see below

   **SMS** (`text` = lowercased `body`, or `""`)
   - `community` — see below
   - `sender_email` — `n` contains `@` → `sms.senderEmailWeight`
   - `keyword:<id>` — for each `keywordRules` entry in file order whose
     pattern is found in `text` → its `weight`
   - `url_ip_host`, `url_shortener`, `url_suspicious_tld` — from the URLs in
     `text` (section 4), in that order, each once → their weights
   - `classifier` — `useClassifier` and `p = classify(body) >= classifier.minProbability`
     → `p * classifier.weight`

   **Community** — `useCommunity`, `n != null`, `community[n] = s` exists and
   `s > 0` → `s * community.weight` (clamped to 1).

7. `score = 1 - Π(1 - weight)` over all signals (0 when there are none),
   clamped to `[0, 1]`.
8. `action = BLOCK` if `score >= thresholds.block`, else `WARN` if
   `score >= thresholds.warn`, else `ALLOW`. `reasons` = signal ids in
   collection order (including signals for an `ALLOW` verdict).

## 4. URLs in message text

`URL_PATTERN` (applied to lowercased text, find all, non-overlapping):

```
(https?://)?(([a-z0-9-]+[.])+[a-z]{2,24}|[0-9]{1,3}([.][0-9]{1,3}){3})(?![a-z0-9-])
```

Capture group 2 is the host. For each host:
- `url_ip_host` if host matches `^[0-9]{1,3}([.][0-9]{1,3}){3}$`;
- `url_shortener` if host equals a `shorteners` entry or ends with `"." + entry`;
- `url_suspicious_tld` if the text after the host's last `.` is in `suspiciousTlds`.

## 5. Classifier — `classify(body) -> probability`

`shared/model/sms_classifier.json`:

```json
{ "version": 1, "bias": -2.1,
  "tokenizer": { "replacements": [ { "pattern": "...", "token": "__url__" }, ... ],
                 "minTokenLength": 2 },
  "weights": { "free": 1.73, "__url__": 0.9, ... } }
```

Tokenize:
1. Lowercase the body.
2. For each replacement in order, replace every match of `pattern` with
   `" " + token + " "`.
3. Split on runs of characters outside `[a-z0-9_]`; drop pieces shorter than
   `minTokenLength`.
4. Take the set of unique tokens.

`logit = bias + Σ weights[t]` for unique tokens `t` present in `weights`;
`p = 1 / (1 + exp(-logit))`. An empty or null body gives `p = sigmoid(bias)`.

## Test vectors

- `normalize.json` — `[{raw, countryCode, expected}]`
- `patterns.json` — `[{pattern, number, matches}]` (`matches` is false when the
  prepared pattern is null/empty)
- `tokenize.json` — `[{text, tokens}]` (sorted unique tokens)
- `classifier.json` — `[{text, probability}]` (tolerance 1e-9)
- `engine.json` — `[{name, event, context, expect: {action, reasons, score}}]`
  (score tolerance 1e-9; omitted fields take the defaults above)
